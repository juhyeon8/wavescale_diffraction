# 금속 막대 회절 시뮬레이션 — 그림자 채움률 S̄ 지표 + 1:1 관찰 모드 설계

> 이 문서는 `docs/superpowers/specs/2026-07-01-zoom-and-view-design.md`(§1~§17)의 후속이다.
> 섹션 번호는 그 문서에 이어 §18부터 시작한다.

## 18. 배경과 목표

기존 구현(§13~§17)까지 완료된 상태: 도선 배열/솔리드 막대 모드, λ/H·Fresnel 수 배지,
H 치수선, 등방화된 3분할 뷰(하한 우선 시 축척비 소표기), I₀·어두운 구간 폭(I<0.5)
지표.

이번 작업의 목표 두 가지:

- **(A) 그림자 채움률 S̄** — "기하 그림자 영역에 회절로 흘러든 에너지"를 프레넬
  진동에 강건한 단일 지표로 정량화한다. 기존 I₀(중심 한 점)는 λ=2~4cm 근접장
  구간에서 값이 출렁이는 반면(§16 각주 참고), 구간 평균인 S̄는 이 진동에 덜
  민감할 것으로 기대된다.
- **(B) 1:1 관찰 모드** — 가로:세로 축척이 항상 정확히 1:1인 전체 화면 관찰
  모드를 추가해, 스크린 거리 L과 무관하게 회절 퍼짐각(θ≈λ/H)을 왜곡 없이
  관찰할 수 있게 한다. 3분할 뷰(§13)는 밴드 하나의 픽셀 종횡비가 작아
  H가 L에 비해 크면 등방이 구조적으로 깨지는 한계가 있었다(§13.3) — 1:1
  모드는 이 한계를 별도 관찰 모드로 우회한다.

**절대 변경 금지(물리 정확도 영역)는 기존과 동일**: `besselJ0`, `besselY0`,
`hankel0`, `solveComplex`, `evalFields`, `screenIntensity`, `recompute()` 안의
MoM 행렬 구성 로직, `colorFor`. 이번 작업 전부 지표 계산/뷰/레이아웃/UI 계층이다.

## 19. 그림자 채움률 S̄ 지표

### 19.1 정의

스크린(x=L)에서 기하 그림자 영역 `|y| ≤ H/2`에 대한 세기 평균(입사 세기=1 기준):

```
S̄ = (1/H) ∫ I(y, L) dy,   |y| ≤ H/2
```

기하광학이라면(회절 없이 빛이 직진한다면) 이 구간은 완전한 그림자이므로 S̄=0이어야
한다. 회절로 에너지가 흘러들수록 S̄가 커진다.

### 19.2 구현

```js
// H_m: 활성 모드 기준 막대 높이(barHeight_mm(state.N, state.d_mm)/1000) —
// 도선 모드든 솔리드 모드든 syncActivePhysics()가 이미 state.N/d_mm을
// 동기화해두므로 별도 모드 분기 불필요.
function computeShadowFillRatio(L_m, H_m, samples = 100) {
  let sum = 0;
  for (let s = 0; s < samples; s++) {
    const wy = -H_m / 2 + (s + 0.5) / samples * H_m;   // |y|≤H/2 균등 100점
    sum += screenIntensity(L_m, wy);
  }
  return sum / samples;
}
```

- 계산 위치는 `updateInfo()` 경로 전용(기존 `computeShadowProfile`의 120점 평가와
  같은 급의 비용 — `screenIntensity`는 이미 순수 포인트 평가라 `recompute()`의
  MoM/그리드 계산에는 영향 없음).
- `selfCheck()`는 실제 `screenIntensity` 의존 없이 순수 검증 가능하도록, 표본
  배열을 직접 받는 헬퍼(`shadowFillRatioFromSamples(samples: number[])`)로
  분리해 단언한다: **`S̄ ≥ 0`만 단언, 상한(S̄ ≤ 1)은 걸지 않는다.** 그림자
  경계 근처의 회절 무늬가 `|y|≤H/2` 구간 안으로 들어오면 국소적으로 입사
  세기(=1)를 넘는 지점이 있을 수 있고, 그 평균인 S̄도 1을 살짝 초과할 수
  있다 — 이는 버그가 아니라 정상적인 회절 간섭 현상이다.

### 19.3 표시

- 정보 박스 순서를 **S̄ → I₀ → 어두운 구간 폭**으로 재배열:
  `"그림자 채움률 S̄ = 0.xxx (기하광학이면 0)"`를 λ/H 다음 줄쯤 눈에 띄게 표시.
- I(y) 플롯에 기하 그림자 구간(`|y| < H/2`)을 파란 계열 옅은 음영
  (`rgba(47,111,235,0.10)`, 기존 accent색 재사용)으로 추가. 기존 I<0.5 음영
  (빨강, §16)과 겹치는 구간은 두 색이 자연히 섞여 보이며, 우측 하단에 소형
  범례 텍스트 한 줄로 "파랑=기하 그림자(|y|<H/2) · 빨강=어두운 구간(I<0.5)"을
  구분 표기한다.
- 힌트 문구(`index.html` 하단)에 한 문장 추가: "S̄는 기하광학이라면 0이어야 할
  그림자 영역에 회절로 흘러 들어온 에너지 비율로, 중심 한 점(I₀)과 달리
  프레넬 진동에 덜 흔들리는 판단 기준입니다."

## 20. 1:1 관찰 모드

### 20.1 핵심 통찰 — 물리 필드는 L과 무관하다

`evalFields(wx, wy, k, wiresY, cRe, cIm, aEff_m)`는 L을 인자로 받지 않는다.
전파하는 물리 필드 자체는 (x,y) 좌표만의 함수이며 L에 의존하지 않는다. L은
현재 3분할 뷰에서 "어디까지 그릴지"(뷰포트 범위)를 정하는 데만 쓰인다(§13.2).
이 통찰이 1:1 모드 설계 전체의 기반이다: **gridWorld(물리 필드가 실제로
계산된 세계 범위)를 충분히 넓게 잡아두면, L이 바뀌어도 이미 계산된 필드
안에서 크롭·크기만 다시 하면 되므로 재계산이 필요 없다.**

### 20.2 좌표계

```
Yw1to1  = 1.25 · (H/2 + 0.05)                          // L 무관, H만의 함수
xSpan1to1 = 2 · Yw1to1 · (bandW / bandH_1to1)          // 밴드 픽셀 종횡비로 역산
xMin1to1  = -xSpan1to1 / 3                              // 장애물(x=0)을 왼쪽 1/3 지점에 배치
xMax1to1  = 2 · xSpan1to1 / 3
```

`bandH_1to1 = cssH - marginT - marginB`(단일 밴드, gap 없음). `bandW`는
3분할과 동일(오른쪽 I(y) 플롯 열 폭 `plotW`는 두 모드 공통 유지).

이 정의상 1:1 모드는 항상 정확히 1:1 등방이다 — §13의 "하한이 등방을 이기는"
문제가 원천적으로 발생하지 않는다(축척비 배지도 뜨지 않음).

### 20.3 gridWorld 공유 — 두 모드 요구치의 합집합

```
gridWorld.xMin = min(baseXmin, xMin1to1) / ZOOM_MIN
gridWorld.xMax = max(baseXmax, xMax1to1) / ZOOM_MIN
gridWorld.Yw   = max(baseYw,   Yw1to1)   / ZOOM_MIN
```

`computeBaseAndGrid()`가 매 `recompute()`마다 3분할 몫(L 기반, 기존 §13.2)과
1:1 몫(H 기반)을 함께 계산해 이 합집합을 잡는다. `camera`(3분할용)와
`camera1to1`을 각각 `base`/`base1to1`을 `view.zoomFactor`로 나눠 산출한다 —
줌 배율은 두 모드가 공유하므로 1:1은 줌 인/아웃 시에도 항상 정확히 1:1을
유지한다.

**결과**: `recompute()`는 지금처럼 N/d/a/λ/L이 바뀔 때만 실행되고(기존과
동일), **모드 전환 자체는 원칙적으로 recompute를 유발하지 않는다** — 아래
20.4의 gridH 예외 하나만 있다.

### 20.4 gridH 해상도 — 지연 확장 전략

3분할 밴드는 세로로 짧아(전체 높이의 1/3) `gridH`가 작아도(현재 기본값 기준
약 227행, recompute ~1~2초) 충분하지만, 1:1 모드는 밴드 하나가 전체 높이를
다 쓰므로 세로로 약 3배 더 길쭉해 같은 방식으로 잡으면 `gridH≈675`가 필요하다
(recompute ~3~6초로 증가).

**결정(사용자 확인)**: `gridH`는 "지금까지 요구된 적 있는 최대 aspect" 기준으로
잡는다 — 처음엔 3분할 기준(작게)으로 시작해 반응성을 유지하다가, **1:1 모드에
처음 진입하는 순간** 필요 aspect가 커진 것을 감지해 그 즉시 1회 recompute로
그리드를 키우고, 이후로는 절대 다시 줄이지 않는다(왕복 전환 시 재계산 없음).
이는 "모드 전환은 절대 recompute 안 함"이라는 요구를 최초 1회만 예외로 완화한
것이며, 그 대가로 평소(3분할 위주) 사용 시 반응성을 지킨다.

### 20.5 렌더링 분기

- `state.viewMode`: `'3band'`(기본) | `'1to1'`.
- `state.viewField`: `'inc'|'sc'|'total'` — 1:1 모드 전용, 기본 `'total'`(③중첩).
- `drawFrame()`이 `viewMode`로 분기: 3분할은 기존 3밴드 루프 그대로, 1:1은
  단일 밴드에 `viewField`가 가리키는 필드 하나만 크롭·렌더.
- `drawOverlay()`도 모드 인지: 1:1은 정의상 항상 등방이므로 축척비 배지는
  절대 뜨지 않는다. H 치수선·도선·진행 화살표는 1:1에서도 동일하게 표시한다.
- **스크린 점선**: `Lx ≤ camera1to1.xMax`면 기존처럼 세로 점선 표시. 초과 시
  (L 슬라이더 범위는 항상 10~300mm 양수이고 `xMin1to1`은 항상 음수이므로
  왼쪽 이탈은 발생하지 않는다) 우측 가장자리에 "스크린 → 오른쪽 밖 xxx mm"
  텍스트만 표시하고 뷰를 늘리지 않는다.
- `drawIntensityPlot(by, bh)`을 인자화해 3분할의 ③밴드 행이든 1:1의 단일
  밴드든 같은 함수로 그린다 — S̄·I₀·어두운 구간 폭 계산 로직은 완전히 공유
  (모드 무관, 현재 L·H만 반영하는 순수 평가이므로).

### 20.6 L 슬라이더의 모드별 동작

- `viewMode==='3band'`: 기존과 동일하게 `scheduleRecompute()`(§13.2, 디바운스
  150ms) — 가로 범위가 L에 종속되므로.
- `viewMode==='1to1'`: gridWorld가 이미 H 기반으로 충분히 잡혀 있어(20.3) L
  변경이 물리 재계산을 요구하지 않는다. `drawFrame()`만 호출 — 스크린 점선
  위치/라벨, I(y) 플롯, S̄/I₀/어두운 구간 폭(모두 `screenIntensity`의 순수
  포인트 재평가)만 즉시 갱신되고, 화면의 회절 무늬 자체는 전혀 바뀌지 않는다.
  **이것이 이번 작업의 핵심 검증 시나리오다(§22.3).**

### 20.7 UI

- "화면 보기 (줌)" 섹션 맨 위에 `.segbtns`(기존 스타일 재사용) 2버튼 토글:
  `[3분할 뷰(기본)] / [1:1 관찰 모드]`.
- 1:1 모드 활성 시에만 그 아래 표시 필드 선택 `.segbtns`(① 입사 / ② 산란 /
  ③ 중첩, 기본 ③) — `wireControls`/`solidControls`의 display 토글과 동일한
  패턴으로 숨김/표시.
- 줌 버튼·휠·"기본 보기" 리셋은 두 모드에서 공유(`view.zoomFactor` 단일 상태).
- 새 CSS 불필요.

## 22. 검증 계획

### 22.1 selfCheck() 신규 단언

- `shadowFillRatioFromSamples`류 순수 헬퍼: `S̄ ≥ 0`만 단언(상한 없음, §19.2).
- `Yw1to1` 공식 단언: 예) H=150mm → `1.25·(0.075+0.05) = 0.15625m`.
- gridWorld 합집합 계산을 담당하는 순수 함수: 3분할 몫과 1:1 몫 중 큰 쪽이
  선택되는지 대표값(예: H가 작아 3분할 몫이 이기는 경우/H가 커 1:1 몫이
  이기는 경우 둘 다)으로 단언.

### 22.2 λ 스윕 — S̄의 프레넬 진동 강건성 확인

솔리드 모드, H=150mm·L=100mm 고정, λ=2/8/24cm 지점에서 (임시 Playwright
스크립트로) λ, N_F, I₀, S̄, 어두운 구간 폭을 표로 출력해 확인:
- S̄가 세 지점에서 단조 증가.
- λ=2~4cm 근접장 구간에서 I₀ 대비 S̄의 출렁임이 크게 완화됨(15점 정도 세밀
  스윕으로 확인).

### 22.3 1:1 모드 핵심 검증 — L 변경 시 화면 불변

1:1 모드에서 L 슬라이더를 10→300mm로 이동해도 화면의 회절 무늬가 전혀
변하지 않아야 한다(스크린샷 비교) — 스크린 점선/라벨과 I(y)·S̄·I₀만 갱신.
이 구간에서 `[성능] recompute()` 콘솔 로그가 찍히지 않는지 확인한다.

### 22.4 회귀 확인

- 3분할 뷰로 되돌렸을 때 기존 동작 100% 회귀(축척비 소표기 포함).
- 도선 모드 λ/d 닿음·투과 배지 등 기존 배지 정상 동작.
- selfCheck() 단언 전부 통과, 페이지 에러 0건.
- "1:1 모드 최초 진입 1회"를 제외하면 모드 전환이 recompute를 유발하지
  않음을 콘솔 로그로 확인(§20.4).

## 23. Self-Review 메모

- 절대 변경 금지 함수 목록 — 이번 작업 어디에서도 건드리지 않는다(§18).
- S̄와 1:1 모드는 서로 독립적이지만, 정보 박스·I(y) 플롯을 공유하므로 하나의
  설계서로 함께 정리했다(사용자 확인). 구현은 S̄ 먼저(위험도 낮음) → 1:1
  모드(뷰 아키텍처 변경, 위험도 높음) 순으로 Task를 나눈다.
- gridH 해상도 트레이드오프는 사용자에게 명시적으로 확인받은 결정이다(§20.4)
  — "지연 확장"(평소엔 작게, 1:1 최초 진입 시 1회 recompute)을 선택했다.
