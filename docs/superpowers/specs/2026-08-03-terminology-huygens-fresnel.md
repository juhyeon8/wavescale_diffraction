# 용어 통일: '하위헌스' → '하위헌스-프레넬' (2026-08-03)

## 1. 변경 사유

화면에 표시되는 원리 명칭을 정식 명칭인 **하위헌스-프레넬 원리**(Huygens–Fresnel
principle)로 통일한다.

이 프로젝트가 비교하는 두 모형은 다음과 같다.

| 모형 | 계산 방법 | 성격 |
|---|---|---|
| 도선 막대 | EFIE-MoM | 엄밀해 |
| 하위헌스-프레넬 | 키르히호프 근사에 의한 프레넬 적분 | 근사해 |

'하위헌스'만 쓰면 "2차 파원이 겹친다"는 정성적 착상까지만 가리키게 된다. 실제로
`compare.js`가 계산하는 것은 프레넬이 도입한 **경사 인자와 간섭 위상**까지 포함한
적분이므로, 정식 명칭인 '하위헌스-프레넬'이 코드가 하는 일과 정확히 일치한다.
지표 박스의 `I₀`·`S̄` 항목은 이미 '하위헌스-프레넬'로 표기되어 있었으므로, 이번
작업은 **한 앱 안에 남아 있던 두 표기를 하나로 맞추는 것**이기도 하다.

## 2. 적용 범위

**표시 텍스트와 주석만** 바꾼다. 물리 계산·로직은 일절 건드리지 않았다.

| 파일 | 변경 건수 | 대상 |
|---|---|---|
| `hub.html` | 3 | `<title>`, ① 탭 라벨, `.mHint` 안내 문구 |
| `hub.js` | 4 | 주석 4곳(단위 환산표, 디바운스 설명, 순차 리로드, §30.7 주석) |
| `compare.html` | 5 | `<title>`, `<h1>`, `.sub`, `#paraxialHint`, λ 스윕 hint |
| `compare.js` | 3 | 주석 2곳, 지표 박스 `Fresnel 수` 각주 |
| `compare-print.html` | 4 | `<h1>`, `.sub`, `#paraxialHint`, λ 스윕 hint |
| `compare-print.js` | 3 | 주석 2곳, 지표 박스 `Fresnel 수` 각주 |
| **합계** | **22** | |

치환 규칙은 정규식 `하위헌스(?!-프레넬)` → `하위헌스-프레넬`이다. 부정 전방탐색이
필수인 이유는 위에 적었듯 일부가 이미 '하위헌스-프레넬'이었기 때문이며, 단순 전역
치환은 `하위헌스-프레넬-프레넬`을 만든다.

### 2.1 문맥상 재작성한 3개 문장

기계적 치환만 하면 '프레넬'이 **원리명**과 **근사명**으로 한 문장에 중복되어 읽기
어려워지는 자리가 있다. `compare.html`·`compare-print.html` 양쪽에 동일하게 적용했다.

- `.sub`
  - before: `… 하위헌스(프레넬 적분, 키르히호프 근사)의`
  - after : `… 하위헌스-프레넬(키르히호프 근사에 의한 프레넬 적분)의`
- `#paraxialHint`
  - before: `하위헌스의 프레넬 근사가 무너져`
  - after : `하위헌스-프레넬 쪽의 근축(프레넬) 근사가 무너져`
- λ 스윕 hint (조사 `과`→`와`, `를`→`을` 교정 포함)
  - before: `도선 막대(엄밀해)과 하위헌스(키르히호프 근사)를 함께 표시하므로,`
  - after : `도선 막대(엄밀해)와 하위헌스-프레넬(키르히호프 근사)을 함께 표시하므로,`

### 2.2 건드리지 않은 것

- **프레넬 수·프레넬 적분 관련 용어**: `Fresnel 수`, `N_F`, `fresnelNumber`,
  `프레넬 적분` 등은 이번 개명과 무관한 별개 개념이므로 그대로 둔다.
- **`huygens/` 폴더 내부 파일**: 이 앱은 화면 어디에도 원리 이름을 적지 않는다
  (`하위헌스`·`호이겐스`·`Huygens` 어느 표기도 0건). 명칭은 전부 허브와 비교
  페이지에만 존재하므로 수정 대상이 아니다.
- **`dist/`**: 난독화 빌드 산출물. 직접 수정하지 않고 재빌드로만 반영한다.

## 3. 코드 식별자는 `huygens`로 유지

한글 표시 명칭만 바꾸고 **영문 식별자·경로는 전부 `huygens`로 둔다.**

`huygens/` 폴더 경로, `data-tab="huygens"`, `#huygensWrap`, `huygensFrame`,
`currentTab === "huygens"`, `needsScrollHuygens`, `recomputeHuygens`,
`computeShadowFillRatioHuygens`, 변수 `huy`, `dirty.huygens` 등이 해당한다.

이유:
1. 식별자 개명은 표시 텍스트 변경과 위험도가 전혀 다르다. `data-tab` 값이나 폴더
   경로는 `hub.js`의 탭 전환·iframe src·postMessage 경로와 얽혀 있어, 한 곳만
   빠뜨려도 탭이 죽는다. 얻는 것은 이름의 정확성뿐인데 잃을 수 있는 것은 동작이다.
2. 학계 관례상 코드 식별자는 짧은 쪽(`huygens`)을 쓰는 편이 일반적이다.
3. `dist/`가 난독화 빌드라 식별자 변경 시 재빌드 대조가 번거로워진다.

## 4. 기존 문서에 소급 적용하지 않음

`docs/superpowers/` 아래의 기존 specs·plans는 **작성 시점의 결정을 남긴 기록**이다.
2026-07-02 설계서와 2026-07-03·07-04 계획서에 남아 있는 '하위헌스' 표기는 그때
그렇게 부르기로 했다는 사실 자체를 담고 있으므로, 한 글자도 바꾸지 않는다.

기록을 뒤늦게 고치면 "그 시점에 무엇을 알고 무엇을 결정했는가"를 잃는다. 대신 이
문서가 그 이후의 변경을 설명하는 역할을 한다. 기존 문서를 읽다가 '하위헌스'를
만나면 이 문서를 함께 참조하면 된다.

같은 이유로 과거 커밋 메시지도 고치지 않는다.

## 5. 허브 탭 라벨 레이아웃

라벨이 `① 하위헌스-프레넬`로 길어지면서 좁은 창에서 줄바꿈이 지저분해지는 문제가
따라온다. `<br>` 하드코딩은 넓은 창에서도 강제로 두 줄이 되므로 쓰지 않았다.

- 번호 뒤 공백을 `&nbsp;`로 바꿔 `①`만 혼자 떨어지는 것을 막는다.
- `.tabBtn`에 `word-break: keep-all`을 줘서 한글 단어 중간이 아니라 **하이픈
  뒤에서만** 끊기게 한다.
- 탭 4개 중 하나만 두 줄이 되어도 높이가 어긋나지 않도록 `display: flex` +
  `align-items: center` + `min-height: 44px`로 높이를 맞춘다. 이때 `padding`은
  `12px 8px` → `10px 8px`로 줄여 한 줄일 때의 버튼 높이를 유지한다.

결과: 넓은 창(1280px)에서는 4개 모두 한 줄, 좁은 창(900px)에서는 ①번만
`① 하위헌스-` / `프레넬` 두 줄로 끊기고 4개 탭의 높이는 서로 같다.

## 6. 배포본 반영

`dist/`는 이 변경을 아직 담고 있지 않다. 기존 플래그로 재빌드해야 반영된다.

```
--string-array false --control-flow-flattening false --self-defending false
```

재빌드는 이 작업 범위 밖이다.
